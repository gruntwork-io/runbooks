The `<Admonition>` block renders a callout box for a note, info, warning, or danger message. It only shows text: it runs nothing, it isn't a step of the runbook's progress, and Runbooks saves nothing of it.

## Basic usage

```mdx
<Admonition
    type="info"
    title="Important Note"
    description="Make sure you have AWS credentials configured before proceeding."
/>
```

## Props

### Required props

- `type` (string): `"note"`, `"info"`, `"warning"`, or `"danger"`. A missing type, or any other, is a configuration error, which shows in the admonition's place.

### Optional props

- `id` (string): an identifier, which a [runbook test](/authoring/testing/) uses to name the admonition. Nothing else refers to an admonition, so it needs none otherwise.
- `title` (string): the heading of the callout box. Without one, or with an empty one, the heading is the type's name: "Note", "Info", "Warning" or "Danger".
- `description` (string): the message, shown above any markdown written inside the block.
- `closable` (boolean): adds a close button (×) that hides the admonition. Default `false`.
- `confirmationText` (string): adds a button with this label that hides the admonition. An empty label is a configuration error.
- `allowPermanentHide` (boolean): with `confirmationText` and `storageKey`, adds a "Don't show me this again" checkbox under the button. See [Don't show again](#dont-show-again).
- `storageKey` (string): the name the hide is kept under, up to 64 characters. It goes with `allowPermanentHide`: either one without the other, or `allowPermanentHide` without `confirmationText`, is a configuration error.

The `title` and `description` show as written. Markdown in them isn't formatted, and neither `{{ .inputs.name }}` nor `{{ .outputs.<id>.<key> }}` is filled in: Runbooks warns of each. To format the message, write it as markdown inside the block.

<Aside type="caution">
`inputsId` doesn't work on an admonition: Runbooks ignores it, with a warning, and shows the admonition's text as written. Earlier versions filled in `{{ .inputs.name }}` and `{{ .outputs.<id>.<key> }}` in its `title`, `description` and `confirmationText`.
</Aside>

## Types

### Note (gray)

```mdx
<Admonition
    type="note"
    title="Note"
    description="This is a general note for additional context."
/>
```

### Info (blue)

```mdx
<Admonition
    type="info"
    title="Helpful Tip"
    description="You can use environment variables instead of hardcoding values."
/>
```

### Warning (yellow)

```mdx
<Admonition
    type="warning"
    title="Caution"
    description="This operation cannot be undone. Make sure you have backups."
/>
```

### Danger (red)

```mdx
<Admonition
    type="danger"
    title="Danger"
    description="This will delete all data in your production database!"
/>
```

A warning's or a danger's confirmation button is red.

## Markdown content

Write markdown inside the block, such as lists, code blocks, and links. It shows under the `description`, when the admonition has one:

````mdx
<Admonition type="info" title="Prerequisites">
Before proceeding, you need:

- AWS CLI installed
- OpenTofu v1.6+
- Valid AWS credentials configured

Check your credentials with:

```bash
aws sts get-caller-identity
```
</Admonition>
````

Put the content on lines of its own, between the opening and closing tags. Content that starts on the same line as the opening tag must end on that line too, and is read as inline markdown:

```mdx
<Admonition type="warning">**Do not** run this in production without testing first.</Admonition>
```

## Closable admonitions

```mdx
<Admonition
    type="info"
    title="Did you know?"
    description="You can skip optional checks using the Skip checkbox."
    closable={true}
/>
```

## Confirmation button

Ask readers to acknowledge the message before it goes away:

```mdx
<Admonition
    type="danger"
    title="Destructive Operation"
    description="This will permanently delete all resources."
    confirmationText="I understand this cannot be undone"
/>
```

A closed or confirmed admonition stays hidden until the runbook is shown again: when it's reloaded, or opened again.

## Don't show again

Let readers hide the admonition for good:

```mdx
<Admonition
    type="info"
    title="Welcome!"
    description="This is your first time running this runbook."
    confirmationText="I've read the introduction"
    allowPermanentHide={true}
    storageKey="welcome-message"
/>
```

When the reader ticks "Don't show me this again" and confirms, the admonition stays hidden every time they open this runbook again, on this computer. Runbooks keeps the hide in its settings, under the runbook's file and the `storageKey`:

- **One runbook only.** An admonition in another runbook with the same `storageKey` still shows. Within a runbook, admonitions that share a `storageKey` are hidden together.
- **The runbook's file.** A runbook moved or copied to another folder shows its admonitions again. So does a runbook opened from a URL, since Runbooks downloads it to a new folder each time.
- **Up to 16 runbooks, with up to 16 hidden admonitions each.** Past that, the runbook hidden in longest ago, or a runbook's oldest hide, is forgotten, and its admonitions show again.

To show the hidden admonitions again, quit Runbooks and remove `hiddenInRunbooks` from `settings.json` in its user data folder.

<Aside>
Earlier versions kept the hide in the window's storage, under the `storageKey` alone, so it hid admonitions with that key in every runbook. Those hides aren't carried over.
</Aside>

## Testing

A [runbook test](/authoring/testing/) step can name an admonition by its `id`. It expects `success` when the admonition is configured, or `config_error`, with `error_contains`, when it isn't:

```yaml
steps:
  - block: welcome
    expect: success
```
