# Watch Mode

Watch mode monitors a `runbook.mdx` file for changes and automatically reloads the runbook in the app.

This feature is intended for **authors** of runbooks.

<Aside type="caution">
Each reload rebuilds the [executable registry](/security/execution-model/#executable-registry) from the files on disk, so after a reload the app executes the current version of your commands and scripts. Pass `--disable-live-file-reload` to keep executing the versions that were present when the runbook was first opened.

Only changes to `runbook.mdx` itself trigger a reload. After you change a script, template, or other file the runbook uses, edit `runbook.mdx` or close and reopen the runbook to load it.
</Aside>

## Activating watch mode

Activate watch mode on the command line when you launch the app:

```bash
runbooks --watch RUNBOOK_SOURCE
```

Watch mode then stays on for every runbook you open until you quit the app.

## Arguments

- `RUNBOOK_SOURCE` - A local path or remote URL pointing to a `runbook.mdx` file or the directory containing a `runbook.mdx` file. See [Opening a runbook](/commands/open) for supported remote URL formats.

<Aside type="note">
When watching a remote runbook, file watching operates on the local downloaded copy. Changes to the remote repository will not be detected automatically.
</Aside>

## Flags

- `--disable-live-file-reload` - Keep the executable registry that was built when the runbook was first opened. Reloads still update what the app shows, but Runbooks keeps executing the original commands and scripts, and blocks whose script has changed show a "Script changed" warning.

## What it does

When watch mode is active:

1. **Watches for changes** - Monitors the runbook file for modifications
2. **Auto-reloads** - Automatically refreshes the runbook in the app when changes are detected (within ~300ms)
3. **Rebuilds the executable registry** - Re-reads the runbook and the scripts it references, unless `--disable-live-file-reload` is set

### Writing a new runbook

```bash
runbooks open --watch /path/to/runbook
```

Then in your editor:
1. Make changes to `runbook.mdx`
2. Save the file
3. See your changes instantly in the app -- no manual refresh needed

## Technical details

### File watching

- Uses `chokidar` for efficient file system monitoring
- Watches the directory containing your runbook file, so editors that save by replacing the file are still detected
- Does not watch subdirectories, such as cloned repositories or generated output
- Implements debouncing (300ms) to handle editors that save files multiple times
- Only triggers on write and create events for your specific runbook file; changes to other files in the directory, such as scripts, are ignored

### Auto-reload mechanism

- Uses IPC (inter-process communication) events to notify the renderer process of file changes
- When the file changes, the main process sends a `watch:file-change` event via IPC
- The renderer receives the event and reloads the runbook, which re-reads the file and rebuilds the executable registry
